# Project Constitution: Todo AI Chatbot – Phase V: Advanced Cloud Deployment (Dapr + Kafka + Cloud K8s + CI/CD)

## Core Principles
- Strict spec-driven & agentic development – no manual coding allowed at any point
- Maximum use of AI-assisted tools (Claude Code, kubectl-ai, Gordon, Dapr CLI)
- Full portability & abstraction: prefer Dapr over direct Kafka/DB libraries
- Security-first: never hardcode secrets, always use Kubernetes Secrets or Dapr secret stores
- Reproducibility: every deployment step must be scripted/automated and documented
- Iterative & incremental: complete one sub-phase fully before moving to next
- Local-first validation: everything must work perfectly on Minikube before cloud

## Key Standards
- All features must be implemented via spec → plan → tasks → Claude Code implementation
- Dapr must be used for Pub/Sub, State, Jobs (reminders), Secrets, Service Invocation
- Kafka/Redpanda must be abstracted via Dapr Pub/Sub component
- Helm charts must be updated to include Dapr sidecars + components
- CI/CD must use GitHub Actions (no manual deploy to cloud)
- Monitoring/logging stretch goal: Prometheus + Grafana + Loki if time allows
- Documentation: README.md must include cloud access URL, setup commands, verification steps
- All YAML/config files must be generated by Claude Code (no manual edits)

## Constraints
- No direct Kafka client libraries in application code (use Dapr Pub/Sub API only)
- No hard-coded secrets in code, values.yaml, or Dockerfiles
- Cloud provider: prefer Oracle OKE (always free) > Azure AKS > Google GKE
- Local testing: Minikube with docker driver + Dapr init -k
- CI/CD: GitHub Actions workflow only (build, test, deploy to cloud on main merge)
- Timeline: complete within hackathon window – prioritize core (features + Dapr + local + cloud deploy)
- No production-grade ingress/TLS unless stretch (use load balancer or port-forward)

## Success Criteria
- All advanced features working (recurring tasks, due dates/reminders, priorities/tags, search/filter/sort)
- Event-driven architecture active: task CRUD → Kafka events → consumers (reminders, recurring, audit)
- Dapr fully integrated: Pub/Sub, State, Jobs, Secrets, Service Invocation
- Application successfully deployed and accessible:
  - On Minikube (local URL via minikube service)
  - On chosen cloud cluster (public URL via load balancer or ingress)
- GitHub Actions pipeline builds, tests, and deploys to cloud on push to main
- Secrets managed securely (Kubernetes Secret or Dapr secret store)
- Deployment survives pod restart & minikube stop/start (state in Neon DB)
- README contains exact cloud access URL + verification commands
- Demo video (≤90s) shows login → create recurring task → reminder triggered → cloud deployment

## Additional Guidelines
- Always reference previous phases' code/charts (Phase IV Helm as base)
- Break Phase V into 5–7 sub-phases (features → Kafka → Dapr → local → cloud → CI/CD)
- Use separate specs/plans per sub-phase
- When generating YAML/components, include validation commands (kubectl apply --dry-run)
- Prefer Redpanda Cloud (free serverless) or Strimzi operator for Kafka
- If any tool fails (quota, access), fallback to self-hosted Kafka in cluster
