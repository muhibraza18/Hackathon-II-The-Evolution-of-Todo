# Data Model: Database Schema for Todo AI Chatbot

**Feature**: Database Schema for Todo AI Chatbot
**Date**: 2026-01-13
**Status**: Draft

## Entity: Task

### Fields
- **id** (Integer, Primary Key, Auto-increment)
  - Unique identifier for the task
  - Auto-generated by the database
- **user_id** (String, Required, Indexed)
  - Identifier for the user who owns this task
  - Enables data isolation between users
  - Indexed for efficient queries by user
- **title** (String, Required, Max 200 chars)
  - Title of the task
  - Cannot be empty
  - Max length of 200 characters
- **description** (String, Optional, Max 1000 chars)
  - Optional description of the task
  - Can be null/empty
  - Max length of 1000 characters
- **completed** (Boolean, Default False)
  - Indicates if the task is completed
  - Default value is False
  - Indexed for efficient filtering of completed vs incomplete tasks
- **created_at** (DateTime, Auto-populated)
  - Timestamp when the task was created
  - Auto-populated by the system
  - Stored in UTC timezone
- **updated_at** (DateTime, Auto-updated)
  - Timestamp when the task was last modified
  - Auto-updated by the system when changes are made
  - Stored in UTC timezone

### Validation Rules
- title must not be empty (length > 0)
- user_id must not be empty
- title length must be ≤ 200 characters
- description length must be ≤ 1000 characters
- completed must be boolean value

### Relationships
- None (standalone entity)

## Entity: Conversation

### Fields
- **id** (Integer, Primary Key, Auto-increment)
  - Unique identifier for the conversation
  - Auto-generated by the database
- **user_id** (String, Required, Indexed)
  - Identifier for the user who owns this conversation
  - Enables data isolation between users
  - Indexed for efficient queries by user
- **created_at** (DateTime, Auto-populated)
  - Timestamp when the conversation was created
  - Auto-populated by the system
  - Stored in UTC timezone
- **updated_at** (DateTime, Auto-updated)
  - Timestamp when the conversation was last modified
  - Auto-updated by the system when changes are made
  - Stored in UTC timezone

### Validation Rules
- user_id must not be empty
- created_at auto-populated on creation
- updated_at auto-updated on modification

### Relationships
- **messages** (OneToMany to Message)
  - One conversation can have many messages
  - Cascade delete: when conversation is deleted, all messages are deleted too

## Entity: Message

### Fields
- **id** (Integer, Primary Key, Auto-increment)
  - Unique identifier for the message
  - Auto-generated by the database
- **user_id** (String, Required, Indexed)
  - Identifier for the user who owns this message
  - Enables data isolation between users
  - Indexed for efficient queries by user
- **conversation_id** (Integer, Required, Foreign Key, Indexed)
  - Reference to the conversation this message belongs to
  - Enforced by foreign key constraint
  - Indexed for efficient queries by conversation
- **role** (String, Required, Enum: "user" or "assistant")
  - Defines who sent this message
  - Either "user" or "assistant"
  - Case-sensitive validation
- **content** (Text, Required)
  - The actual content of the message
  - Cannot be empty
  - No length limit (unlimited text length)
- **created_at** (DateTime, Auto-populated, Indexed)
  - Timestamp when the message was created
  - Auto-populated by the system
  - Stored in UTC timezone
  - Indexed for chronological ordering

### Validation Rules
- user_id must not be empty
- conversation_id must reference an existing conversation
- role must be either "user" or "assistant"
- content must not be empty
- conversation_id must exist in Conversation table

### Relationships
- **conversation** (ManyToOne to Conversation)
  - Many messages belong to one conversation
  - Foreign key constraint ensures referential integrity
  - Cascade delete behavior configured

## Relationships Summary

### Message ↔ Conversation
- **Type**: Many-to-One
- **Foreign Key**: Message.conversation_id → Conversation.id
- **Constraint**: ON DELETE CASCADE
  - When a Conversation is deleted, all related Messages are automatically deleted
- **Indexing**:
  - Message.conversation_id is indexed for efficient lookups
  - Message.created_at is indexed for chronological ordering

### User Isolation
- All entities (Task, Conversation, Message) have user_id field
- All queries should filter by user_id to maintain data isolation
- This ensures one user cannot access another user's data

## Indexing Strategy

### Primary Indexes
- Each entity has a primary key index on id (auto-created)

### Secondary Indexes
- **user_id** (on all 3 entities): For efficient user-based filtering
- **Task.completed**: For efficient filtering of completed/incomplete tasks
- **Message.conversation_id**: For efficient conversation-based message retrieval
- **Message.created_at**: For chronological ordering of messages

## State Transitions

### Task State Transitions
- **Created**: New task with completed=False
- **Completed**: Task status changes from False to True
- **Reopened**: Task status changes from True to False (optional)
- **Deleted**: Task is removed from database

### Conversation State Transitions
- **Started**: New conversation is created
- **Active**: Messages are exchanged in the conversation
- **Ended**: Conversation is archived/deleted (with cascade delete of messages)

### Message State Transitions
- **Created**: New message is added to a conversation
- **Deleted**: Message is removed (via cascade when conversation is deleted)

## Data Integrity Constraints

### Referential Integrity
- Foreign key constraints ensure Message.conversation_id references existing Conversation.id
- Cascade delete ensures related messages are removed when conversation is deleted

### Domain Constraints
- Role field restricted to "user" or "assistant" values
- Boolean fields properly constrained
- Required fields enforced at database level

### Length Constraints
- Task.title limited to 200 characters
- Task.description limited to 1000 characters
- All other text fields have appropriate constraints
