# Claude Code Instructions - Todo Evolution Phase I

## Project Overview

**Project Name:** Todo Evolution - Phase I (In-Memory CLI Todo Application)

**Purpose:** A hackathon demonstration of agentic development workflows using Spec-Kit Plus methodology.

## Development Workflow

### 1. Specification Phase

When asked to work on this project:

1. **First**, check `specs/` for existing specifications
2. **Review** `constitution.md` for project rules and principles
3. **Always** follow the spec-driven development approach:
   - Write/update specification in `specs/`
   - Archive previous versions to `specs/history/`
   - Create plan using spec-planner agent
   - Implement using python-implementer agent

### 2. Code Generation Rules

- **ALL code must be generated by agents** - no manual typing
- **Use python-implementer agent** for Python code
- **Follow PEP8 standards** - maximum 88 char line length
- **Use UV for environment** - never use pip or conda
- **In-memory storage only** - no files or databases
- **Built-in modules only** - no external dependencies

### 3. Project Structure

```
phase_1/
├── src/
│   └── main.py          # All application code
├── specs/
│   ├── initial-spec.md   # Current specification
│   ├── implementation-plan.md
│   └── history/         # Archived specs
├── constitution.md
├── CLAUDE.md           # This file
├── README.md
└── .gitignore
```

## Required Agents and Skills

For this project, use these specialized agents:

1. **spec-writer** - Create or update specifications
   - Use when user asks to specify features
   - Follow spec format from `specs/initial-spec.md`

2. **spec-planner** - Create implementation plans
   - Use after specification is ready
   - Follow implementation plan format

3. **python-implementer** - Generate Python code
   - Use for all Python code generation
   - Follow PEP8 and clean code principles

## Command Reference

### For Specification Work
```
/sp.specify [feature]    # Create specification for feature
/sp.plan                 # Create implementation plan
/sp.implement             # Generate code from plan
/sp.tasks                # Show current task list
```

### For Code Quality
- Run `uv run ruff check src/` for linting
- Run `uv run ruff format src/` for formatting
- Fix any PEP8 issues before submitting

## Testing

### Manual Testing Checklist

When testing, follow the manual testing checklist in `specs/implementation-plan.md`:

1. Add Task - 6 test cases
2. List Tasks - 5 test cases
3. Update Task - 6 test cases
4. Delete Task - 6 test cases
5. Toggle Status - 5 test cases
6. Edge Cases - 7 test cases

### Demo Script

For hackathon demonstration, follow the demo script in `specs/implementation-plan.md`.

## Key Principles

1. **Spec-driven** - Never write code without specification
2. **Agentic** - Always use agents, never manual coding
3. **PEP8** - Clean, Pythonic code
4. **Simple** - In-memory only, no complexity
5. **Documented** - Docstrings for all functions

## Common Tasks

### Adding a New Feature
1. Write specification using spec-writer agent
2. Archive old spec to `specs/history/`
3. Create implementation plan using spec-planner agent
4. Implement using python-implementer agent
5. Run manual testing checklist
6. Update README.md if needed

### Fixing a Bug
1. Describe bug in specification format
2. Use python-implementer to fix
3. Run relevant test cases
4. Document fix in spec history

### Code Review
- Check PEP8 compliance
- Verify all 5 features work
- Test edge cases
- Check documentation

## Phase I Scope (Do NOT Expand)

This Phase I intentionally includes:
- ✅ Add, list, update, delete, toggle status
- ✅ In-memory storage (list of dicts)
- ✅ CLI interface with numbered menu
- ✅ Auto-incrementing IDs

Do NOT add in Phase I:
- ❌ File persistence
- ❌ Database storage
- ❌ Web interface
- ❌ Advanced features (priorities, due dates, search)
- ❌ Multi-user support
- ❌ Testing framework (unittest/pytest)
- ❌ CI/CD

These are reserved for future phases.
