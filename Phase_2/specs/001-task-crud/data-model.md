# Data Model: Task CRUD Operations

**Branch**: `001-task-crud` | **Date**: 2026-01-07 | **Phase**: 1

## Overview

This document defines the data model for the Task CRUD Operations feature, including entity definitions, field specifications, relationships, and database schema.

## Core Entity: Task

### Entity Definition

**Task**: Represents a work item with title, description, completion status, and ownership.

**Purpose**: Enables users to track, manage, and complete work items through the task management application.

### Field Specifications

| Field | Type | Length | Required | Description | Validation |
|-------|------|--------|----------|-------------|------------|
| id | String (UUID) | 36 | Yes | Unique identifier for the task | Auto-generated |
| user_id | String | Variable | Yes | Owner of the task (future auth) | Fixed to "test-user-1" |
| title | String | 1-200 | Yes | Task title/name | 1-200 characters |
| description | String | 0-1000 | No | Detailed task description | 0-1000 characters |
| completed | Boolean | N/A | Yes | Task completion status | Default: false |
| created_at | DateTime | N/A | Yes | Timestamp when task was created | Auto-generated |
| updated_at | DateTime | N/A | Yes | Timestamp when task was last updated | Auto-updated |

### Field Descriptions

#### id
- **Purpose**: Unique identifier for referencing tasks
- **Type**: UUID (Universally Unique Identifier)
- **Format**: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`
- **Generation**: Auto-generated by database
- **Indexing**: Primary key, automatically indexed

#### user_id
- **Purpose**: Associates task with a specific user
- **Type**: String (variable length)
- **Value**: Fixed to "test-user-1" for this phase
- **Future**: Will store actual user IDs from authentication system
- **Indexing**: Indexed for efficient user-specific queries

#### title
- **Purpose**: Brief task name or identifier
- **Type**: String
- **Length**: 1-200 characters (inclusive)
- **Required**: Yes
- **Validation**: Cannot be empty, maximum 200 characters
- **Usage**: Displayed prominently in task list

#### description
- **Purpose**: Detailed information about the task
- **Type**: String
- **Length**: 0-1000 characters (inclusive)
- **Required**: No
- **Validation**: Can be empty string, maximum 1000 characters
- **Usage**: Provides context and details for task completion

#### completed
- **Purpose**: Indicates whether task is finished
- **Type**: Boolean
- **Values**: `true` (completed) or `false` (incomplete)
- **Default**: `false`
- **Usage**: Controls visual styling and filtering

#### created_at
- **Purpose**: Timestamp of task creation
- **Type**: DateTime
- **Format**: ISO 8601 (e.g., "2026-01-07T12:00:00Z")
- **Generation**: Auto-generated on creation
- **Immutable**: Never changes after creation
- **Indexing**: Indexed for sorting by creation date

#### updated_at
- **Purpose**: Timestamp of last modification
- **Type**: DateTime
- **Format**: ISO 8601 (e.g., "2026-01-07T13:30:00Z")
- **Generation**: Auto-updated on any modification
- **Mutable**: Updates on title, description, or completed changes

## Relationships

### User Ownership
**Relationship**: Many-to-One (Tasks → Users)
- **From**: Task.user_id
- **To**: User.id (future)
- **Description**: Each task belongs to exactly one user
- **Current State**: All tasks owned by dummy user "test-user-1"
- **Future State**: Tasks owned by authenticated users

## Database Schema

### PostgreSQL Schema (Neon)

```sql
-- Enable UUID extension
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- Users table (prepared for future auth)
CREATE TABLE IF NOT EXISTS users (
  id VARCHAR(255) PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  name VARCHAR(255),
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Tasks table
CREATE TABLE IF NOT EXISTS tasks (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id VARCHAR(255) NOT NULL,
  title VARCHAR(200) NOT NULL,
  description TEXT CHECK (LENGTH(description) <= 1000),
  completed BOOLEAN NOT NULL DEFAULT false,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- Indexes for performance
CREATE INDEX idx_tasks_user_id ON tasks(user_id);
CREATE INDEX idx_tasks_created_at ON tasks(created_at DESC);
CREATE INDEX idx_tasks_completed ON tasks(completed);

-- Composite index for user tasks sorted by date
CREATE INDEX idx_tasks_user_date ON tasks(user_id, created_at DESC);
```

### Index Strategy

**Primary Indexes**:
- `tasks.id`: Primary key, auto-created
- `tasks.user_id`: Foreign key, indexed for user queries
- `tasks.created_at`: Indexed for sorting by creation date

**Secondary Indexes**:
- `tasks.completed`: Indexed for filtering by completion status
- `tasks(user_id, created_at)`: Composite index for user task queries

**Rationale**:
- user_id index: Required for all user-scoped queries (99% of queries)
- created_at index: Supports sorting tasks by creation date
- completed index: Enables filtering by status (e.g., "Show only incomplete")
- Composite index: Optimizes common query pattern (user's tasks sorted by date)

## SQLModel Implementation

### Task Model (Python)

```python
from sqlmodel import SQLModel, Field, Session, select
from typing import Optional
from datetime import datetime
from uuid import uuid4

class TaskBase(SQLModel):
    """Base model with shared fields"""
    title: str = Field(min_length=1, max_length=200)
    description: Optional[str] = Field(default=None, max_length=1000)

class TaskCreate(TaskBase):
    """Schema for task creation"""
    user_id: str = "test-user-1"  # Fixed for this phase

class TaskUpdate(SQLModel):
    """Schema for task updates"""
    title: Optional[str] = Field(default=None, min_length=1, max_length=200)
    description: Optional[str] = Field(default=None, max_length=1000)

class TaskResponse(TaskBase):
    """Schema for task responses"""
    id: str
    user_id: str
    completed: bool
    created_at: datetime
    updated_at: datetime

class Task(TaskBase, table=True):
    """Database model for tasks"""
    id: str = Field(default_factory=lambda: str(uuid4()), primary_key=True)
    user_id: str = Field(foreign_key="users.id")
    completed: bool = Field(default=False)
    created_at: datetime = Field(default_factory=datetime.utcnow)
    updated_at: datetime = Field(default_factory=datetime.utcnow)
```

## Validation Rules

### Title Validation
```python
title: str = Field(
    min_length=1,
    max_length=200,
    description="Task title (1-200 characters)"
)
```

**Rules**:
- Must not be empty (minimum 1 character)
- Maximum 200 characters
- Cannot be whitespace only
- Trailing/leading whitespace should be trimmed

**Error Messages**:
- Empty title: "Title is required"
- Too long: "Title must be 200 characters or less"
- Whitespace only: "Title cannot be empty"

### Description Validation
```python
description: Optional[str] = Field(
    default=None,
    max_length=1000,
    description="Task description (optional, 0-1000 characters)"
)
```

**Rules**:
- Optional field (can be None or empty string)
- Maximum 1000 characters
- Whitespace allowed (can be multi-line)

**Error Messages**:
- Too long: "Description must be 1000 characters or less"

## Data Lifecycle

### Task Creation
```
1. User submits TaskCreate form (title, description)
2. Backend validates inputs (Pydantic)
3. Task instance created with:
   - id: Auto-generated UUID
   - user_id: "test-user-1"
   - title: User input
   - description: User input (or None)
   - completed: false
   - created_at: Current timestamp
   - updated_at: Current timestamp
4. Task saved to database
5. Created task returned as TaskResponse
```

### Task Update
```
1. User submits TaskUpdate form (title, description)
2. Backend validates inputs (Pydantic)
3. Task loaded from database by id
4. Fields updated:
   - title: New value (if provided)
   - description: New value (if provided)
   - updated_at: Current timestamp
5. Task saved to database
6. Updated task returned as TaskResponse
```

### Task Completion Toggle
```
1. User clicks complete button
2. Task loaded from database by id
3. completed field inverted (true ↔ false)
4. updated_at set to current timestamp
5. Task saved to database
6. Updated task returned as TaskResponse
```

### Task Deletion
```
1. User clicks delete button
2. Task loaded from database by id
3. Task deleted from database
4. Empty response returned (204 No Content)
```

## Data Integrity Constraints

### Database Constraints
- **Primary Key**: tasks.id must be unique
- **Foreign Key**: tasks.user_id must reference valid user
- **NOT NULL**: title, user_id, completed, created_at, updated_at cannot be null
- **CHECK**: description length ≤ 1000 characters
- **DEFAULT**: completed defaults to false, timestamps default to CURRENT_TIMESTAMP

### Application Constraints
- **Title Length**: 1-200 characters (Pydantic validation)
- **Description Length**: 0-1000 characters (Pydantic validation)
- **User ID**: Fixed to "test-user-1" (application layer)
